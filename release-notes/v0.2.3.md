# Chef Hand-off for MDL3 0.2.3

**Chef Shared Loader 1.4.x 和 1.5.x 都请用这一版。** 让 **Chef Shared Loader**（以及 HUDdle、Treasure Radar 等只能在它下面运行的 mod）和 **MDL3**（以及 BF5 击杀反馈这类 MDL3 mod）在同一个 Helldivers 2 里一起工作：这个 mod 由 MDL3 启动，进游戏 6 秒后用 Chef 文档里写明的办法把游戏交给 Chef。没装 Chef，或者 Chef 已经在运行时，它什么也不做。

## 和 0.2.0 比（0.2.1、0.2.2 没有单独发布）

- **Chef 的卡死看门狗。** Chef 被交接时会收下游戏全局表上当时的 `update`、`render`、`shutdown`（MDL3 自己的），在自己的回调之后运行。这些回调在它的卡死看门狗下面（看门狗是 Chef 1.4.0 加的，1.4.1 和 1.5.x 都是）：一次调用超过 3 秒就判卡死，整条链被关掉（Chef 的日志里是 `switched off boot:... for this session: it hung`），MDL3 也就停了。
  所以交接时先把这些回调从**游戏的全局表**上摘下，Chef 加载完再放回它自己的回调后面（Chef 的先，MDL3 的后）。Chef 自己的 mod 照常受看门狗保护；Chef 没起来时，回调原样放回。
- **为什么是 0.2.3。** 0.2.1、0.2.2 摘的是本 mod 自己的 `_G`。真机日志显示 MDL3 让每个 addon 在自己的沙箱里运行，`_G` 不是游戏的全局表，所以它们只摘掉了 `render`，MDL3 的 `update`、`shutdown` 一直被 Chef 收着。0.2.3 改在游戏的全局表上摘（`getfenv(0)`，Chef 的核心读的就是它）。那张表要是守着它没有的键，就换上空的替身而不是摘下。
- `chef_handoff.log` 记得更多，排查时有用：用的是哪张表、交接前后那里的回调各是什么；交接后 MDL3 的更新每帧跑几次（一次是对的）；MDL3 的某次调用超过 0.5 秒 CPU 时间时的一行；交接前后的调试钩子。

## 安装

1. 下载下面的 `Chef-Hand-off-for-MDL3-0.2.3.zip`，加进 Arsenal / HD2 Mod Manager 并启用（替换旧版本）。你已经有：MDL3、Chef Shared Loader（1.2.0 以上）和要用的 mod。
2. **MDL3 的优先级要比 Chef 高**（游戏运行的 boot 必须是 MDL3 的）。Arsenal 里：设置是 *First mod highest priority* 就把 MDL3 放在 Chef 上面，是 *Last mod highest priority* 就放在下面。
3. Purge，再 Deploy。启动游戏，在标题画面停 10 秒以上，再进一局任务。

成功的样子：`%APPDATA%\Arrowhead\Helldivers2\chef_handoff.log` 里有 `Chef Shared Loader ... started`，稍后有 `the game's update chain ran 600 times in the first 600 frames after the hand-off: once a frame`；`chef_loader.log` 里有 `started by MDL3 chef_handoff 0.2.3, which handed off to me`，没有 `running the callbacks ... set before it started me`。各种现象怎么判断、要附哪些日志：见仓库里的 `handoff/README.md`。

## 验证到了哪一步

- **真机**（作者的游戏，MDL3 3.0.0-dev.29，HUDdle 0.6.11，Treasure Radar 0.7.1n，BF5 击杀反馈 MDL3 版 2.0.1）：0.1.0 和 0.2.0 配 Chef 1.4.1，0.2.1 和 0.2.2 配 Chef 1.5.1，交接都成功，HUDdle、Treasure Radar、BF5 正常。0.2.1、0.2.2 下 Chef 仍收下了 MDL3 的两个回调（就是上面说的沙箱）。
  **0.2.3 配 Chef 1.5.1**：跑起来正常；Chef 的日志里没有 `running the callbacks ...` 了，Chef 没有收下 MDL3 的任何回调，MDL3 的更新每帧一次、在 Chef 后面（`chef_handoff.log`：`the game's global table: getfenv(0) ...`，`once a frame`）。
- **模拟器**（Chef 自带的，真实的 Chef 代码，1.4.1 和 1.5.1；1.5.1 是官方发布的那个包，用标签 `v1.5.1` 的源码重新构建，zip 逐字节一样）：照 0.2.2 的真机日志做了一个 MDL3 沙箱的替身，加一次 3.6 秒的慢调用。
  0.2.2 在它上面逐行写出和真机一样的日志，真实的 Chef 1.5.1 写出同样的 `... (2)`，并在慢调用上把 MDL3 判成卡死、关掉；0.2.3 下 Chef 不收下任何回调，慢调用跑完，MDL3 照常更新。0.2.3 的全部检查在 1.4.1 和 1.5.1 上都通过（86 项，加真实的 HUDdle 是 90 项）。
- **不知道的**：评论里说的“Chef 1.5.1 判 MDL3 卡死”，真实的 MDL3 是哪次调用超过了 3 秒（作者的机器上没有出现过；0.2.3 下 MDL3 的更新已经不在看门狗下面，模拟器里这种慢调用没事）。

## 已知的问题

- Chef 的 mod（HUDdle 之类）在 MDL3 自己的菜单和日志里会显示错误（`enable failed`）：MDL3 给它们的不是 Chef。这是 MDL3 眼里的失败，实际是 Chef 在运行它们，游戏里能正常用。
- 有一次启动时，MDL3 设置里所有 mod 的分类都显示“未知”（名字正常）。那次 MDL3 自己读文件的服务在启动时就坏了（`MDL.log` 里 `attempt to index upvalue 'kernel' (a nil value)`），比交接早 6 秒；下一次同样的安装就正常了。看起来是 MDL3 自己时有时无的问题。
- 0.1.0 下任务中按 ESC 回飞船闪退过**一次**，原因没找到，之后没有再出现。
- 只在 MDL3 3.0.0-dev.29（"protected preview"）上测过。

反馈问题时请附上 `chef_handoff.log`、`chef_loader.log` 和 `MDL.log`（`MDL.log` 每次启动会被覆盖，先拷出来再重开游戏）。

## English

Use this version with Chef Shared Loader 1.4.x and 1.5.x. Chef (from 1.4.0, when its hang watchdog came) runs the callbacks it is handed (MDL3's own update, render and shutdown on the game's global table) under its hang watchdog and switches them off when one call takes over 3 s, which stops MDL3. The hand-off takes those callbacks off while Chef loads and puts them back behind Chef's own.
0.2.1 and 0.2.2 took them off the addon's own _G, but MDL3 runs every addon in a sandbox of its own (the 0.2.2 log showed it), so Chef kept MDL3's update and shutdown all along. 0.2.3 takes them off the game's global table (getfenv(0), where Chef's core reads them), with empty stand-ins instead if that table guards new keys.
Real game: 0.1.0/0.2.0 with Chef 1.4.1 and 0.2.1/0.2.2/0.2.3 with Chef 1.5.1 worked (HUDdle, Treasure Radar, BF5 feedback); with 0.2.3 Chef kept none of MDL3's callbacks and MDL3's update ran once a frame behind Chef's. Also verified in Chef's own simulator with the real Chef 1.4.1 and 1.5.1, under a stand-in for MDL3's sandbox built from the 0.2.2 log. Install the zip below, enable it, and give **MDL3 a higher priority than Chef**, then Purge and Deploy. MIT license.
