# Chef Hand-off for MDL3 0.2.6

让 **Chef Shared Loader**（以及 HUDdle、Treasure Radar、NarrowHUD 等只能在它下面运行的 mod）和 **MDL3**（以及 BF5 击杀反馈这类 MDL3 mod）在同一个 Helldivers 2 里一起工作：这个 mod 由 MDL3 启动，进游戏 6 秒后用 Chef 文档里写明的办法把游戏交给 Chef。

## 和 0.2.5 比

- **交接成功后，状态文件不会再停在 `attempt`**（[issue #4](https://github.com/JFRedist/HD2-Chef-Handoff-for-MDL3/issues/4)）。0.2.5 下，有玩家每次交接成功后 `chef_handoff_state.txt` 都停在 `attempt 0.2.5`，下一次启动就当作“上次在交接中崩溃”，不再交接，每次都得先删掉这个文件。现在 Chef 一加载完就写状态并读回核对，没写进去就在后面的帧里再写；之后的每一步出了错，MDL3 的回调也照样放回去。
- **上一次启动的日志留作 `chef_handoff.previous.log`。** 状态写着 `attempt`，而上一次的日志表明那次交接已经完成时，照常交接；真在交接里崩了的，照旧不再试。旧版本留下的 `attempt`（比如 0.2.5 的）会再试一次，所以从 0.2.5 升级时不用手动删文件。
- MDL3 重新启动本 mod 时不再清空日志；没有 `os` 库时补丁扫描也能跑。
- 别的行为和 0.2.5 一样。Chef Shared Loader 1.5.3、MDL3 3.0.0-dev.43 和 HD2 Data Hub 0.6.0 都查过，交接不用改。

## 安装

1. 下载下面的 `Chef-Hand-off-for-MDL3-0.2.6.zip`，加进 Arsenal / HD2 Mod Manager 并启用（替换旧版本）。你已经有：MDL3、Chef Shared Loader（1.2.0 以上）和要用的 mod。
2. **MDL3 的优先级要比 Chef 高**（游戏运行的 boot 必须是 MDL3 的）。用 Rat's Shared Loader 的话，Rat 也放在 MDL3 下面。
3. **本 mod 放在最低优先级。**
4. Purge，再 Deploy。启动游戏，在标题画面停 10 秒以上，再进一局任务。

成功的样子：`%APPDATA%\Arrowhead\Helldivers2\chef_handoff.log` 里有 `back from require (attempt ...): Chef Shared Loader ... started`，`chef_handoff_state.txt` 是 `ok 0.2.6`，`chef_loader.log` 里有 `started by MDL3 chef_handoff 0.2.6, which handed off to me`。

## 已知的问题

- issue #4 那位玩家那里 `ok` 为什么没写进去，没有查到（出事那次的日志被下一次覆盖了）；最可能是写文件时文件正被别的程序占着。0.2.6 会重写，并把原因写进日志（`chef_handoff_state.txt could not be written (...)`）。
- 用 Rat 时，Chef 的 F9 里 Rat 运行的 mod 写的是 “Run by MDL3 chef_handoff”；Rat 的加载画面会显示 READY WITH WARNINGS（它要求放最高）；Rat 的回调在 Chef 的卡死看门狗下面。
- MDL3 3.0.0-dev.33 只看前 512 个补丁文件：补丁文件一多于 512，跟 MDL3 一起放在最高的 HD2 Data Hub 就不会被 MDL3 启动。这要 MDL3 修。

## 验证到了哪一步

- **自写测试** 159 项；**Chef 自带的模拟器**（真实的 Chef 1.4.1、1.5.1 和 1.5.3）86 项：全过。新加的测试里，0.2.5 有 19 项不过（状态写不进去时卡在 `attempt`、`require` 之后出错时 MDL3 的回调回不去等）。
- **真机**（作者的游戏，MDL3 3.0.0-dev.43 + HD2 Data Hub 0.6.0，Chef 1.5.3）：0.2.6 连续启动两次，每次都交接成功，状态文件都是 `ok 0.2.6`；第二次启动时，第一次的日志留成了 `chef_handoff.previous.log`。第一次进了一局任务，约 23 分钟，Chef 退出 `shutdown (clean)`。0.2.5 在同样的版本上也测过，交接正常。

反馈问题时请附上 `chef_handoff.log`、`chef_handoff.previous.log`、`chef_loader.log` 和 `MDL.log`（`MDL.log` 每次启动会被覆盖，先拷出来再重开游戏）。

## English

0.2.6 fixes the state file being left at "attempt" after a hand-off that worked (issue #4): with 0.2.5 a player on Chef 1.5.3 and MDL3 3.0.0-dev.43 had every launch after a working one skip the hand-off, until the file was deleted. The mark is now written and read back as soon as Chef has loaded, and written again on later frames if it did not land; every step after that is protected, so MDL3's callbacks always go back. The last launch's log is kept as chef_handoff.previous.log: an "attempt" mark whose launch the old log shows got past the hand-off no longer blocks it, and a mark left by an older version gets one more try (no need to delete it when you update from 0.2.5).
Install: add the zip below to your mod manager and enable it, give **MDL3 a higher priority than Chef** (and than Rat, if you use it), give **this mod the lowest priority**, then Purge and Deploy.
Verified with 159 checks of its own and 86 in Chef's simulator with the real Chef 1.4.1, 1.5.1 and 1.5.3, and in the real game with MDL3 3.0.0-dev.43, HD2 Data Hub 0.6.0 and Chef 1.5.3: two launches in a row, each handed off with the state file at "ok 0.2.6", the second keeping the first one's log; one mission of about 23 minutes, clean shutdown.
